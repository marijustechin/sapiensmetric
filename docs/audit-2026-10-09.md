### Corrected — duplicate-answer defect (medium impact)

`docs/assessments.md` guarantees that malformed save payloads — including
**duplicate entries** — are rejected as `400 INVALID_ANSWERS`, and the scoring
core already detects duplicates. However the service merged entries by `itemId`
(last-wins) **before** validation, and `saveAnswersRequestSchema` did not enforce
uniqueness, so a duplicate payload was silently accepted (HTTP 200).

- Fix: `packages/contracts/src/assessment.ts` `saveAnswersRequestSchema` now
  `.refine`s unique `itemId`s; the controller already maps a failed `safeParse` to
  `400 INVALID_ANSWERS`.
- Regression (contract): `packages/contracts/src/assessment.spec.ts` (accepts
  distinct, rejects duplicates, allows clear+set of different items).
- Regression (HTTP/controller boundary, Docker-free):
  `apps/api/src/modules/assessment/assessment.controller.spec.ts` drives the real
  controller through Fastify HTTP with the real `AssessmentService` and an
  in-memory store, and asserts: duplicates → **HTTP 400 `INVALID_ANSWERS`** with
  **no store interaction** (so seeded answers/revision are unchanged); a malformed
  payload → 400 before any store interaction; a valid unique payload → 200 with
  exactly one `saveAnswers` call and the revision advanced.
- Supporting change: `AssessmentController` now uses explicit
  `@Inject(AssessmentService)` (matching the other controllers), so the
  dependency resolves under test runners that do not emit `design:paramtypes`.
- Also broadened the answer-key isolation grep in `verify.sh` invariant 22 from
  the assessment feature directories to the whole `apps/web` tree (no false
  positives today).

### Corrected — harness weaknesses (medium impact)

- **Public-release verification was outside the gate and could pass against a
  stale artifact.** `pnpm verify` rebuilt `apps/web/out` but never rebuilt or
  verified `dist/public-site`, so `verify-public-release.sh` could validate bytes
  from an earlier build. Fixed by:

    already produced) and refuses `.htaccess`/`.well-known` in the export/artifact;

    **file-for-file and content-for-content** (a recursive `diff -r --brief`

    changed JS/CSS, missing files **and** unexpected extra files, not only a
    changed `index.html`;

    `build-public-release.sh --no-build` → `verify-static-export.sh` →

  `deploy-webdav.mjs` now expects `404` for `/en/assessment/` and `/lt/assessment/`

  artifact.

- **`noindex` coverage in `verify-static-export.sh`** now asserts every auth page

## Deliberately not changed (recommendations / remaining risks)

- **No CI.** Every guarantee depends on a human running `pnpm verify`. Recommend a
  minimal GitHub Actions workflow (`pnpm install --frozen-lockfile && pnpm verify`).
- **Reproducibility is documented precisely and deliberately not over-claimed**
  (`docs/deployment-webdav.md` "Reproducibility terminology"): **repeatable release
  generation** is established (freshness-checked file set); **byte-identical
  independent builds are not claimed**, because the Next build id and hash-named
  assets are build-scoped. Artifact identity remains **content-based** over the
  exact artifact. Do **not** pin `generateBuildId` merely to stop the identifier
  changing: that alone does not make the build reproducible, and pursuing
  byte-reproducibility needs its own justified, recorded decision.
- **`deploy:verify` checks HTTP status only** (no remote byte comparison). Byte
  identity is verified manually; recommend a content-verification mode.
- **Integration tests are not in the default gate** (they need local MySQL).
- **Route exclusions are a hard-coded 4-name list**; a future private route could
  ship silently. Recommend deriving them from the `(app)` route group.
- **Task-archive bookkeeping in `verify.sh` invariant 3** (≈60 exact heading/status
  greps) is low-value and inflates the pass count; recommend consolidating to a
  structural check. Left intact here to avoid churn.
- **Claims guard** keeps a duplicate rule list and scans source catalogues only
  (not rendered HTML); recommend importing `PRODUCT_COPY_RULES` and scanning the
  export.
- Unchanged external follow-ups: manifest `Content-Type`, custom-404
  ErrorDocument, Search Console ingestion (unconfirmed), GA4 settings/report
  review, API deployment, hosting migration plan.
